# T-49 — AutoLaris payment adapter contract and signed-reference callback (track `t49`)

Isolated worktree on top of the wave 1 overlay (T-59 expand, T-60, T-74; migration 0011). Nothing committed or deployed, no provider called, no
real secret. Everything runs against the **fake** AutoLaris adapter; sandbox evidence and vendor status codes stay DEFERRED (D-22 item 5).
Authority: ADR-0006 decision 6, D-20 (quality bar), D-21 K (callback = verify-by-pull), D-22 (named settings, no invented numbers).

## What changed

The old contract (`PaymentAdapter.createInstruction({storeId, orderId, amount}) -> {reference, instructions}`, a flat string stored in
`order.payment_reference`, a worker handler that skipped when a reference existed) is **replaced end to end**; no shim remains.

New (`packages/db/src/payments/`)
- `contract.ts` — structured types (`PaymentCreateInput` with a persisted `reffId`, `channelCode`, customer, amounts, expiry, owner kind/id;
  `PaymentInstruction` with reference, provider transaction id, VA, unmodified QR, payment code, URL, expiry, amounts, provider fee),
  `parseListPayment`, `buildSubmit` (the 24-key `courir_id: 1` profile, `cod_value: "0"`, `grand_total = String(buyer payable)`), `parseSubmit`
  (`rc === "00"` first, exactly one populated instruction field, ≤ 2048 chars, https-only URL, total equals ours), `expiryStampWib`,
  `classifyAdvice`, `paymentFee`/`feeLabel` (explicit base per channel), `PaymentContractError`.
- `fake.ts` — `FakeAutoLaris`: channel list, every instruction form, logical rejection, malformed answer, provider down, lost response after
  creation, inquiry crash, a bill replay by `reff_id`; **no network, no transport code exists**.
- `signature.ts` — `callbackToken` / `verifyCallbackToken`: `?cb=<reff>.<hmac128>`, `HMAC-SHA256(AUTOLARIS_CALLBACK_SECRET, "pay-callback:v1:" + reff)`
  truncated to 32 hex, constant-time compare, fail closed without a ≥ 32-byte secret.
- `schema-payments.ts` + migration `0012_t49_autolaris_payments.sql`: `payment_attempt` (owner kind/id, `reff_id` unique, request state
  `in_progress|accepted|failed|unknown`, status `pending|paid|unknown`, immutable `amount/admin_fee/total` with `total = amount + admin_fee`,
  `transaction_id`, structured `instruction` jsonb, revision, poll counters), `payment_attempt_event`, `payment_callback` (digest, shape,
  raw body, quarantine mark), `payment_observation`, `late_payment_obligation`; `order.payment_reference` is dropped.
- `attempts.ts` — `createOrderPaymentAttempt` (in the checkout transaction: `reff_id`, amounts, first event and the instruction job commit
  with the order, before any provider call), `awaitStoredResult`, `paymentCreateInput`, `storeInstruction`, `markCreationOutcome`,
  `recordPaymentInquiry` (the only settlement path), `assertPaymentOwner`, `setCallbackRetention`, `redactPaymentCallbacks`.
- `callback.ts` — `acceptPaymentCallback` (HTTP-17 core, **app pool**): signature → size → JSON → identity → definer resolver for the store →
  binding (`reff_id`, provider transaction) → amount equals `total_idr` → digest row (`ON CONFLICT DO NOTHING`) → one `payment.verify` job.
- `jobs.ts` — `payment.instruction` (fenced with `markDispatched` right before the single `/submit`), its reconciler, `payment.verify`
  (fenced inquiry) and its reconciler (reconciles by pulling, never by re-dispatching), `pollAdvice` + `payment.advice_poll` (JOB-25, observe-only,
  `registerSchedule` minute period) and `payment.callback_redact` (daily). `setPaymentAdapter` feeds the reconcilers.
- `view.ts` — `orderPaymentView`: what buyer and seller may see (never the provider transaction id, provider fee or callback data).
- `settings.ts` — named settings (below). `providers.ts` — new `PaymentAdapter` (`listChannels`, `submit`, `advice`, optional `recoverCreate`).

Web (`apps/web`)
- `(public-services)/api/payments/autolaris/callback/route.ts` — HTTP-17: bounded body read, per-IP + global fixed-window limit, code-only answers
  (403 binding, 400 identity/malformed, 422 amount, 404 unknown, 413, 429, 503 no secret), `no-store`.
- Checkout page: channels come from the provider list with their fee label; `actions.ts` forwards `paymentChannel`.
- Confirmation page: structured instruction (VA / payment code / https link / QR payload byte for byte in a read-only textarea), WIB expiry,
  fee and "Total tagihan"; copy says **Bukalaris Bayar**, never the vendor. Seller order detail shows channel, total and verification state.
- `playwright.config.ts`: fixed e2e `AUTOLARIS_CALLBACK_SECRET` (the spec signs callbacks); `.env.example`: dev placeholder.

Changed shared files (minimal): `schema.ts` (drop `order.payment_reference`, export the new schema), `index.ts` (exports), `platform/isolation-registry.ts`
(5 tables, 3 definer functions, `signal_event` platform `INSERT`), `platform/resolvers.ts` (`resolvePaymentAttemptStore`),
`drizzle-pending/t59-contract.sql` (grants of the new tables + `signal_event` INSERT, so the contract test stays exact), `ops/jobs/jobs.ts`
(old payment handler and constant removed; built-in policy for the new kinds), `ops/ops.ts` (module `api.payments` for the route map),
`seller/commerce/checkout.ts`, `seller/commerce/orders.ts` (payment view on `getOrder`; the `pay` history note may be supplied), `worker.ts`
(one import), `demo/seed-demo.ts` (channel + owner-side reset of payment rows), `test/helpers.ts` (`buyer()` default `paymentChannel`),
`vitest.config.ts` (`env.AUTOLARIS_CALLBACK_SECRET`), `rls-contract.test.ts`, `checkout.test.ts`, `jobs.test.ts`, `orders.test.ts`

## Decisions and defaults taken (all revisable; none is a vendor fact)

1. **One attempt per order** (`UNIQUE(store_id, order_id)`): the same request replays the same row/`reff_id`; anything else is refused. A new
   payment after expiry = a new checkout (an expiry/retry policy is not specified).
2. **`reff_id`** = 29 decimal digits from 96 random bits (provider limit 30 digits; unguessable; unique).
3. **`manual_transfer` stays the payment-method key** of orders (prepaid through the gateway); the buyer selects a channel with it. Channels are the
   provider's list ∩ channels the platform fee schedule can price (`paymentFees`: QRIS 0.7% of goods omset, VABCA Rp6.500, other VA Rp3.000,
   e-wallet 3.0% of payable: values given by ADR-0006; rounding half up is my choice). COD is not a gateway channel.
4. **Settings** (`payments/settings.ts`, D-22): `ADVICE_SETTLED = []` (live settlement off), `ADVICE_STATUS_FIELD = "status"`, `ADVICE_AMOUNT_FIELD =
   "amount"` (response schema unpublished: if the vendor uses other fields nothing settles), `ADVICE_PAID_STATUS = "PAID"`, `ADVICE_MAX_POLLS = 24`,
   `ADVICE_INTERVAL_MS = 300 000`, `PAYMENT_INSTRUCTION_LIFETIME_MS = 24 h`, `ADVICE_BATCH_SIZE = 24`, `CALLBACK_BODY_MAX_BYTES = 16 KiB`,
   `AUTOLARIS_CALLBACK_LIMIT` 120/min per IP (1200/min global), callback retention `null` (the older 30-day proposal is NOT adopted: OPEN).
5. **Who settles**: only `recordPaymentInquiry` from a *pulled* inquiry (`callback` verification or `reconcile`); the poll is observe-only. For the
   fake adapter settlement is enabled (that is what the tests exercise); a `live` adapter settles only when `ADVICE_SETTLED` contains `PAID`
   (owner decision in writing). Seller "Tandai sudah dibayar" stays the operator-confirmed path.
6. **Order payment goes through the single status writer** (`applyTransition(..., "pay")`), actor `system:payment-inquiry`; a payment verified
   for a cancelled/returned order is `paid` for audit only and inserts a `late_payment_obligation` (the buyer's whole payable incl. the gateway
   fee, D-20 item 7); no order payment, no Purchase signal, no credit.
7. **Callback runs on the app pool**: the store comes from the signed reference through the definer resolver `resolve_payment_attempt_store(text)`;
   no new `platformDb()` use in `apps/web` (the import-boundary test stays green). Evidence tables are tenant class; the platform role holds no
   DELETE on payment tables, `payment_callback` is `SELECT` only, and the raw body is blanked only by the owner-side `redact_payment_callbacks()`.
8. **Database guards** (plain trigger functions): `payment_attempt_guard` (identity and amounts immutable, `paid` never regresses, `paid_at`,
   transaction id, instruction written once, resolved creation state final, revision monotonic), `payment_evidence_guard` (events,
   observations, obligations: no update, delete only inside `reset_demo_payments`), `payment_callback_guard` (only redaction).
9. **Demo seed**: its platform pool cannot delete evidence, so `reset_demo_payments(bigint[])` (owner-side definer, only stores with the reserved
   `demo-%` slug) clears the payment rows; seeding needs `AUTOLARIS_CALLBACK_SECRET` like any worker.
10. **No backfill**: existing `awaiting_payment` transfer orders only hold old fake references (no provider was ever called); a `payment.instruction`
    job for such an order finds no attempt and ends.

## DEFERRED (exact missing input)

- **Sandbox / real calls and vendor codes** — owner approval for a sandbox call and a sanitized observed response: where the inquiry carries status and
  amount (`ADVICE_STATUS_FIELD`, `ADVICE_AMOUNT_FIELD`), whether `PAID` is the settlement word, `rc` set. Until then `ADVICE_SETTLED = []`.
- **`/submit` explicit expiry acceptance** and the **`callback_url` payment-vs-tracking ambiguity** (does `/submit` call back for payment?) —
  AutoLaris confirmation. Account approval of `courir_id: 1` and the production IP whitelist (≤ 5) are live prerequisites.
- **Callback body retention period** — privacy owner (PRIV-7). The function and job exist and do nothing until a period is set (`setCallbackRetention`, `ops.jobs.manage`).
- **QR image rendering** — needs a QR encoder (a dependency decision, `native-first`); the payload is shown unchanged as text today.
- **Owner console screens** for unknown payment instructions and open `late_payment_obligation` rows, and the refund disbursement itself — T-62 / T-37.
  Recovery of a live unknown creation is manual (no `recoverCreate` is invented for a live account).
- **Subscription-invoice attempts** — T-50 (the contract has the owner kind; this task wires order attempts only).
- **Per-reference callback rate limit** — only per IP and global are built.
- **Deploy**: `AUTOLARIS_CALLBACK_SECRET` (≥ 32 bytes) and `PLATFORM_ORIGIN` must be set for web and worker (`docs/DEPLOY-COOLIFY.md`, not edited).

## Decisions and defaults
- **Theme values** are `responsive` (default) and `mobile` as briefed (openapi.yaml says `mobile-480`; the orchestrator can rename at merge — one enum + one CHECK). Theme is a `store` column; switching changes only the shell: `data-theme="mobile"` caps `.sf-shell` at 480 px and centres it; pages adapt via container queries on `<main>` (`@2xl`, `@3xl`, `@5xl`), so no page component knows the active theme. Checkout has no storefront theme (ARCH-7).
- **Capabilities**: settings require `role === "owner"` (checked in `content.ts`, no change to `scoped.ts`); collections/pages/media reuse `catalog.read`/`catalog.write` (owner + staff).
- **Media**: bytes are sniffed (JPEG SOF, PNG IHDR, WebP VP8/VP8L/VP8X) and dimensions read from the header — the file name and declared type are ignored. Limits: 5 MB, 10 images per product, ≤ 10000 px per side. Files live at `MEDIA_DIR/<storeId>/<mediaId>.<ext>`; the row is written first and the file inside the same transaction (`persist` callback) so a failed write leaves no orphan row. Public route serves only images of **active** products of the host/path-resolved store with `Cache-Control: public, max-age=31536000, immutable` (ids never change; deletion yields 404); the seller preview route is session + membership scoped with `no-store`. `<img>` carries `width/height/loading/decoding`; no sharp, no resizing.
- **Collections**: ordered membership replaced on every save; foreign products rejected in the service (`foreign_product`) and by the compound FK. Storefront shows only `published` collections and only `active` members, in collection order.
- **Pages**: markdown-lite (`#`–`###`, paragraphs, `-`/`1.` lists, `**bold**`, `*italic*`, `[text](https://…)`) rendered to React elements; no HTML parsing, links limited to http(s)/mailto/same-site paths. Reserved slugs: `products, collections, pages, search, cart, checkout, media, admin, seller, api, login, account, invite, s, lp, sitemap, robots`.
- **Search**: ILIKE over title/description of active products, wildcards escaped, query ≤ 100 chars, 24 results (`// lazy` note: upgrade to tsvector + GIN when catalogs grow).
- **WhatsApp**: normalised to `62…` (strips `+`, leading `0` → `62`, separators), Indonesian numbers only; rendered as a `wa.me` link in the footer.
- **Store create (SA-03)** picks the owner by existing user email; invitations are out of scope (accounts track).
- No delete for collections/pages (archive = set to draft) — YAGNI for M2.

## Docker / deployment note
`MEDIA_DIR` must be a persistent volume in the web container (e.g. `-v bukalaris_media:/app/var/media` or `MEDIA_DIR=/data/media` with a mount) — the runner image runs as `app` (non-root), so the mount must be writable by that user. `apps/web/Dockerfile` was not changed (no docker build run in this track).

## Open issues / ceilings
- Object storage (S3/R2) adapter: `lib/media.ts` is the single seam (`writeMedia/readMedia/unlinkMedia` by key).
- No image resizing/thumbnails (sharp not in the build); listings load the original file with `loading="lazy"` and reserved dimensions. Upgrade: resize on upload once an image library is approved.
- Images of a product deleted via DB cascade leave files on disk (no product delete flow exists yet); a sweeper keyed on `media` rows is the upgrade path.
- Theme enum naming vs openapi (`mobile` vs `mobile-480`), collection cover image, menus (SC-09), SEO fields, content revisions (DATA-6) are not implemented.
- Search is ILIKE; full-text/GIN when needed.
- Seller product delete/archive of images is immediate (no undo).

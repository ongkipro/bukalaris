## Decisions and defaults

- **Capability model.** `operator_grant(user_id, capability)` with
  `capability ∈ {logs.read}`; FK to `platform_operator` so a seller can never
  hold a grant (membership is not a path to it). `requirePlatformCap` runs
  before any query; a denied read writes no audit row and no diagnostic row.
  Upgrade path: add capabilities to `PLATFORM_CAPABILITIES` + CHECK.
- **Redaction = allowlist, then scrub.** Only `LOG_FIELD_ALLOWLIST` keys reach
  stdout or the sink: `module, operation, page_id, store_id, request_id, code,
  route, method, status, outcome, provider, duration_ms, error_name, digest`.
  Structured identifiers are kept verbatim (capped 200 chars). Free text
  (`message`) is scrubbed: `params: …` tails (Drizzle's "Failed query" carries
  bound values), URLs (credentials/query strings), `Bearer/Basic` tokens,
  emails, digit runs ≥ 9 (phones/cards), then capped at 500 chars. Passwords,
  tokens, cookies, addresses, phones, nested objects are dropped by
  construction. `onRequestError` records only route template, method,
  correlation id, error name, digest, code — never URL query, headers, cookies
  or bodies.
- **Sink.** Postgres table in the same database (no external service: local-only
  rule). Writes are fire-and-forget with a 2 s race; failure writes one
  `ops.sink` warn line to stdout and never fails the caller. Only warn/error/
  fatal are persisted; info/debug stay on stdout.
- **Retention.** Not automated. Indexes support `delete from system_log where
  time < now() - interval '30 days'`; the duration is a deployment gate per
  16-OBSERVABILITY ("Unknown until capacity evidence"). The detail page says
  "tidak ditemukan atau sudah melewati masa simpan" for a missing id.
- **Access audit** reuses `audit_log` (`logs.list` with the normalized filter
  JSON as reason, `logs.read` with `event:<id>`), separate from `system_log` so
  opening the viewer never lists itself.
- **Query bounds.** Default window = last hour; maximum 24 h; `from < to`
  enforced; limit 50 (max 200); cursor = last seen id with `(time desc, id desc)`
  ordering; cursor pagination freezes `from/to` in the URL. Timestamps shown in
  WIB explicitly (viewer zone unknown server-side).
- **Environment / release.** `APP_ENV` (default `production`/`development` from
  `NODE_ENV`) and `RELEASE_REVISION ?? SOURCE_COMMIT` (Coolify sets the latter);
  absent → `rilis tidak diketahui`.
- **Error page ceiling.** When a server component throws before the shell is
  flushed, Next 16 returns status 500 with an HTML shell whose body is the root
  `error.tsx` boundary rendered client-side (`__next_error__`). Users with JS
  see the Indonesian page with request id + digest; a JS-less client gets an
  empty 500 shell, not a stack trace. `global-error.tsx` covers a failing root
  layout. `not-found.tsx` reads the id server-side (SSR-visible).
- **e2e events** are a controlled fixture written through the real
  `recordLogEvent` (OBS-5 "synthetic canaries in controlled fixtures"), not a
  dev-only trigger route. The real error path is proven by the DB-unreachable
  test (below).

## Open issues

- External sink/alerting: none (local-only). Hook: `emit()` in `lib/log.ts` is the single place to add a forwarder (OTLP/Loki) later; the stdout JSON lines are already collector-friendly.
- Retention job and stale/partial source states are not implemented (no ingestion delay exists with a same-DB sink); the UI shows "Kesegaran tidak tersedia" when the window is empty.
- `log.warn/info` is not yet called from other tracks' server paths (their files are not editable here); only `onRequestError` and the Log System pages emit today. Suggested call sites at merge: checkout `placeOrder` failure (`module: "checkout"`), store suspension (`admin.stores`), sign-in rate limit (`auth`).
- `x-request-id` acceptance assumes the reverse proxy strips/overwrites client-supplied ids when it mints its own; the strict shape check limits log injection but does not prove provenance.
- Not verified: Docker image builds (out of scope for this track), behaviour on a JS-less client beyond "empty 500 shell, no stack".

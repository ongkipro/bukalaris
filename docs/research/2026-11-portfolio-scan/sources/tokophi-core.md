# TokoΦ (tokophi-core) — findings for Bukalaris

## Source summary
- TokoΦ is a live multi-tenant Shopify-style commerce SaaS for Indonesia (Next.js admin, Astro storefront, Postgres with RLS, KiriminAja shipping, AutoLaris payments). It has been in production since 2026-07-13.
- The most mature material is the working contract (`AGENTS.md`, 1414 lines, same file as `CLAUDE.md`) plus the `specs/docs` audits. `FINANCE.md`, `SLA-DRP.md`, `CUSTOM_DOMAIN.md` and `AUDIT_PAYMENT_CHECKOUT.md` carry the incident detail.
- The date range is roughly 2026-07 to 2026-10-29.
- Coverage is partial. I read `AGENTS.md` by section and sampled `FINANCE`, `SLA-DRP`, `CUSTOM_DOMAIN` and `AUDIT_PAYMENT_CHECKOUT`. I did not read `BUILD-LOG`, `CHANGELOG`, `KIRIMINAJA`, `DEPLOY`, `SECURITY`, `PATTERN_UIUX` or `audit-2026-08-01` end to end.
- Bukalaris already absorbed much of TokoΦ's money and ledger lessons (ADR-0006, ADR-0009, ADR-0011, `docs/11`). I therefore list mainly gaps, and mark overlaps "Partly covered".

## Findings
| # | Theme | Finding | Class | Source evidence | Bukalaris target | Pri |
|---|---|---|---|---|---|---|
| 1 | RLS / child tables | Tables with no `store_id` need an explicit rule. Before any write, every parent id and FK in the values must be read back from an RLS-protected table in the same transaction, and the action must bail if that read is empty. Otherwise the parent write silently no-ops for a foreign id while the child write lands. This produced five shipped cross-tenant bugs, and `verify-rls` cannot see the class because it derives coverage from `store_id` columns. | Invariant | `AGENTS.md:348` | `docs/06-TENANT-ISOLATION.md`, ADR-0005 (rg "child table" found nothing). New rule and test. | P1 |
| 2 | RLS / identity table | The table that identifies the tenant (`stores`, keyed by `id`) had no RLS. Two reads used `.from(stores).limit(1)` inside the tenant wrapper and returned an arbitrary store. Any query on a table without `store_id` must filter on `storeId` explicitly, and the policy is only the safety net. | Invariant | `AGENTS.md` (Database section, near line 340) | `docs/06`, ADR-0005; check that the verifier covers `id`-keyed tenant roots | P1 |
| 3 | RLS / pools | The "restricted" runtime pool actually ran as `rolsuper` and `BYPASSRLS`, behind a label. The fix: verify the connected role against `pg_roles` once per process before the first tenant query, and exit if it fails. A restricted pool with no `APP_DATABASE_URL` must refuse to start rather than fall back to the owner URL. Paths with no tenant must stay on the owner pool, because moving them to the restricted role returns 0 rows. | Invariant | `AGENTS.md:332-339` | ADR-0005 and `docs/12`; check for a boot-time role proof | P1 |
| 4 | Migrations | Drizzle applies the whole pending batch in ONE transaction, so a single "already exists" rolls back every later migration while printing success (16 migrations were left unapplied on a shared dev DB). Write every migration idempotent (`if not exists`, enum `duplicate_object` guards). | Invariant | `AGENTS.md:76` | `docs/15-DELIVERY-MIGRATIONS.md` (rg "single transaction" found nothing). Add a lint or check. | P1 |
| 5 | Migrations | A migration stamp (`when`) that is too high silently skips another branch's migration. Drizzle applies only entries newer than the newest recorded stamp, so when renumbering after a merge collision you must re-stamp as well. Confirm with `select max(created_at) from drizzle.__drizzle_migrations` on the target. `verify-migrations` fails on a duplicate index, a non-increasing `when`, and a journal entry with no `.sql` file. | Invariant | `AGENTS.md:83` | `docs/15`; new CI check | P1 |
| 6 | Migrations | `drizzle-kit generate` against stale snapshots replays shipped work and emitted `ALTER TYPE … ADD VALUE`, which has no `IF NOT EXISTS`. They hand-write migrations by copying a recent one. | Candidate | `AGENTS.md` ("MIGRATIONS HERE ARE WRITTEN BY HAND", near line 300) | `docs/15`; only relevant if Bukalaris snapshots drift | P3 |
| 7 | Dev data | Seed dates anchored to a fixed day rot: charts empty out, and `current_period_end` lapses so every admin save fails with a suspended error. The fix was an idempotent insert-only "seed:recent" that also moves a lapsed period forward. Truncating the shared DB costs other agents their session. | Invariant | `AGENTS.md:~50-62` | `docs/tracks/demo.md`, DEMO.md (has `--reset`; check for an insert-only refresh) | P2 |
| 8 | Dev data | A destructive seed must refuse when rows that nothing writes back exist (orders, ledger, encrypted tracking tokens). A "keep list" for a store-scoped table is a no-op because TRUNCATE CASCADE follows the FK. It needs a second explicit variable. | Invariant | `AGENTS.md:~63-75` | `docs/tracks/demo.md` | P2 |
| 9 | Shipping | The quote and the booking must describe the same box. Quoting by weight only while booking sends dimensions made one parcel's real cost 4× the quote (Rp13.700 vs Rp54.800), which the merchant absorbed. Dimensions are part of the rate cache key, and no volumetric divisor is hard-coded (the vendor varies it). | Invariant | `AGENTS.md:662` | ADR-0006 mentions volumetric. Verify the quote path sends dimensions and that they are in the cache key. | P1 |
| 10 | Shipping | The waybill is NOT in the booking response (`awb: null` is normal). A poller fills it later, and the booking ref must never be stored as the AWB. Label printing is blocked until the AWB exists. A sidecar that stops quietly left `awbFilled` at 0 for a week. | Invariant | `AGENTS.md:~690-715` | Partly covered (ADR-0006, `docs/05`). Add a poller-liveness alert. | P2 |
| 11 | Shipping | Cancel takes the AWB only, never the order id. The window where a booking has no AWB is exactly when people cancel. Refuse before calling the vendor and name the next step. A non-COD void can queue up to 48h, so "accepted" does not mean "cancelled". | Invariant | `AGENTS.md:718` | Partly covered (ADR-0006 has `cancel.*awb`). Add the UI wording and the queued-void state. | P2 |
| 12 | Shipping | Pickup is scheduled for the next day at 10:00 WIB, computed in `Asia/Jakarta`, because couriers enforce cut-offs. A test that books `now+1h` is correctly refused. | Current-source required | `AGENTS.md:733` | `docs/ADR-0007`, tracks/shipping (rg "cut-off" found nothing). Re-verify with Mengantar. | P3 |
| 13 | Shipping / sandbox | Sandbox and production return identically shaped bookings, so a deploy on the wrong environment looks healthy ("dibooking", resi appear) while no courier collects. The default env was sandbox. Surface the active env on an operator screen. | Invariant | `AGENTS.md` (Shipping section, `KIRIMINAJA_ENV` bullet) | Partly covered (rg "sandbox.*production" hit `docs/04`, DEPLOY-COOLIFY). Check for a visible env badge. | P1 |
| 14 | Shipping / COD | COD is a fact about the order (`payments.method`), never a parameter. `createShipment` must derive it and refuse a disagreeing caller. The old code let a bulk loop use the SERVICE's COD capability, which would have told the courier to collect cash again on 67 prepaid orders. A stored-vs-claimed COD amount is also what credits "withdrawable" money for cash nobody took. | Invariant | `AGENTS.md:1027` | `docs/17`, ADR-0006; confirm the booking derives COD from payment | P1 |
| 15 | COD policy | The COD gate is a chain of agreements (platform enabled and cap, provinces, courier `codAllowed`, store opt-in default false). One function answers "may this be COD", and the order endpoint is the boundary while the checkout is UX. Show the unmet reason instead of silently hiding COD. | Candidate | `AGENTS.md:~700-715` | rg "province" and "Rp2.000.000" found nothing; `docs/tracks/t48-fix.md` has `codAllowed` only. Needs an owner decision. | P2 |
| 16 | COD money | The platform fronts the seller's COD cash. The seller is credited at `selesai`, but the courier remits days to weeks later, and the schema has no `cod_settled_at` or reconciliation against the courier's COD report. Exposure is bounded only by the release rule and the minimum payout. | Invariant | `FINANCE.md` (§4 ledger, COD remittance gap bullet, ~lines 178-190) | Partly covered (`docs/11`, DECISIONS). Verify a remittance fact, not only a delivered status, is recorded. | P1 |
| 17 | Ledger | Anything that sums the balance must not join `orders`: payout rows have a NULL `order_id`, so an inner join drops them and the available balance jumped from Rp21,0 jt to Rp43,7 jt (measured on production). Likewise `not exists (… orders …)` is TRUE for NULL, so the obvious orphan query reports every withdrawal as corruption. | Invariant | `AGENTS.md:1055` | `docs/05`, `docs/11`; add a balance-view test | P1 |
| 18 | Ledger | The sale-credit function must exclude both `batal` and `retur`. Excluding only `batal` let a late payment callback credit a returned order as withdrawable. Double-credit is prevented by DB-level partial unique indexes plus `on conflict do nothing`, with the balance derived and no stored column. | Invariant | `AGENTS.md:1046` | Partly covered (ledger_one_sale found in ADR-0006). Verify `retur` is in the exclusion test. | P2 |
| 19 | Ledger | A terminal order must never get a live bill. Creating a payment for a cancelled order lets the buyer pay and the credit then skip it, so money is collected and no sale is credited. Refuse at creation, and also refuse a second bill while one is pending. | Invariant | `AGENTS.md` (Order lifecycle, "A terminal order must never grow a live bill") | `docs/11` payment-create path | P1 |
| 20 | Payouts | Payout completion is one compare-and-swap (`… where status='diproses' returning`). Previously `menunggu → selesai` was legal, so a never-started transfer was marked paid. A locked re-read gives the error message only and must not become the decision. The same pattern was applied to refunds. | Invariant | `AGENTS.md:619`, `FINANCE.md` (§4 refunds bullet) | Partly covered (rg "payout.*transition" hit ADR-0006). Verify the refund CAS and transfer-reference fields. | P2 |
| 21 | Refunds | A paid prepaid order that is cancelled or returned owes the buyer, and the debt needs its own row in the same transaction as the claw-back. Refunding the buyer posts nothing to the seller ledger. COD never produces one. One open row per payment, enforced by a partial unique index. The dashboard shows it as its own tile and never sums it with seller payables. | Candidate | `FINANCE.md` (§4 refunds bullet) | Partly covered (DECISIONS OPEN-F4 on buyer refund). Check the data model has an obligation row per payment. | P2 |
| 22 | Payment callback | Audit found no amount or currency verification on the callback, no unique constraint on `reff_id`, no timeout on the gateway call that runs after the order commit, local-time expiry stamps with no pinned TZ, and no expiry sweep for stock held by unpaid orders. | Invariant | `AUDIT_PAYMENT_CHECKOUT.md:80-84` | Partly covered (Advice-by-pull in `docs/11:107`; rg "TZ" hit TASKS and ADR-0006). Confirm a stock-hold expiry sweep and a gateway request timeout exist. | P1 |
| 23 | Payment callback | A reusable secret never goes in a URL. Sign the reference instead (`?cb=<reff>.<hmac>`) and bind it to the row. Keep a vendor-required bare-token door open until the vendor supports a header. Refusing it would 401 every genuine payment. Zero identifiers is a 400 and an ambiguous match is a 400. | Invariant | `AGENTS.md:1293` | Covered (`docs/11:107` has the `?cb=` form). Check the "do not close the vendor door" note. | P3 |
| 24 | Public API | Read bodies through a size-capped stream reader, because `req.json()` accepted a 64 MB body. Cap `items[]` on the raw array (10,000 items took 63.8 s of DB work in one request). Do not add a bot gate to money endpoints, because an empty User-Agent would silently refuse real orders. | Invariant | `AGENTS.md:1288` and the "readPublicBody" bullet near it | `docs/09`, `docs/16` (rg "MAX_CART" and "body size" found nothing) | P1 |
| 25 | Public API | A provider's own error text must never reach a shopper (it said the aggregator's name in the first person). Substitute our own messages, log the original, and show the provider's words only to the seller. | Invariant | `AGENTS.md` (public API section, "A PROVIDER'S OWN ERROR TEXT") | Partly covered (`docs/13` brand-hiding). Add a test for the two public routes. | P2 |
| 26 | Rate limit | Rate limiting started as per-process memory, so it multiplied with replicas and reset on deploy. It moved to one DB row per key, but the decision is still made from a local cache with a write-behind merge. The first call per key per replica is answered before the shared count is known, and a burst can overshoot. Making it async is the shape to move to. A per-account failure streak was added alongside the IP limit. | Invariant | `AGENTS.md:~560-580`, `AUDIT_PAYMENT_CHECKOUT.md:83` | `docs/16` already uses Postgres counters. Check the async-decision point and per-account streak (rg "write-behind" found nothing). | P2 |
| 27 | Super-admin | The operator's rank is read from `platform_admins` on every request, never from the cookie. A demoted, deleted, or password-rotated operator kept full power for the 7-day JWT. Route-entry floors per page group were added (additive to action gates), and a new page with no floor fails closed. | Invariant | `AGENTS.md:389-437` | ADR-0011, `docs/07` (rg "route floor" hit ADR-0011 only). Verify per-request rank and page-level gating. | P1 |
| 28 | Impersonation | Impersonation is a one-time exchange (opaque 256-bit handle, only its sha256 stored, one `UPDATE … WHERE consumed_at IS NULL RETURNING`). The session is bounded to 30 minutes and carries the operator identity. Membership and rank are re-read at consume time. Every gated write while impersonating writes an audit row naming both parties and fails closed. | Invariant | `AGENTS.md:401` | Partly covered (ADR-0011, tracks/t63). Check the dual-identity audit and fail-closed write. | P1 |
| 29 | Suspension | An operator suspension is a separate fact from billing (`suspended_at`). One column cannot carry both: abuse suspension must survive payment, and non-payment lock must auto-lift. The money paths read `billingStatus`, not the effective status. The Suspend button once did nothing while the audit said it worked. | Invariant | `AGENTS.md:608` | Covered (ADR-0011 suspension semantics). Confirm `billingStatus` drives billing and renewal invoices. | P3 |
| 30 | Billing | Manually marking an invoice paid is bookkeeping and does not extend the subscription. Entitlement moves on payment events only. The UI copy, toast and audit line all say so. | Candidate | `AGENTS.md` ("MARKING AN INVOICE PAID BY HAND IS BOOKKEEPING") | `docs/11` (needs an owner ruling) | P2 |
| 31 | Dashboard numbers | Money on a screen is derived live from `orders`. A frozen rollup table written only by the seed gave empty dashboards. The daily series must be dense and end on today (`generate_series` left join), and day bucketing uses one WIB definition. A missing denominator renders "—", not +0%, and a good/bad signal never relies on colour alone. | Invariant | `AGENTS.md:974` | `docs/17`, tracks/dashboard (rg "generate_series" found only a gap report) | P2 |
| 32 | Checkout forms | `<form novalidate>` is load-bearing so every validation message is in Indonesian rather than the browser's language. `readOnly` silently cancels `required`. Never call `reportValidity()` on blur because it steals focus (a typed address ended up in the email field). Postal code is required, auto-filled and always editable. | Invariant | `AGENTS.md:1226-1230` | `docs/17` (rg "novalidate", "reportValidity", "kode pos" found nothing). Add to the checkout screen contract and test. | P1 |
| 33 | Checkout input | Normalise generously, reject narrowly: phone is canonical `62…` with no hard-coded carrier prefixes, email is shape-only and optional, names allow apostrophes and diacritics. Over-validation costs sales silently. | Invariant | `AGENTS.md:~1215-1222` | Partly covered (rg "over-validation" found nothing; check `packages` validators). | P2 |
| 34 | Abandoned cart | Abandonment is the absence of an order, so capture is a debounced beacon with fail-quiet semantics. `abandoned_at` is the moment it went quiet. The naive recovery rate was 19,3% where the truth was 11,2%, because ordinary sales also end as "recovered". Recovery uses signed store-bound tokens, and the UI records "WA dibuka", never "terkirim". | Invariant | `AGENTS.md:331` | Partly covered (rg "WA dibuka" hit `docs/17`, PRD). | 35 | Storefront speed | Third-party marketing pixels cost the most: mobile went 90 → 66 and TBT 130 ms → 770 ms. They load on first interaction with a 10 s backstop and synchronous stubs. | 36 | Tracking | A conversion is built from the order row, not the success page. ## Anti-patterns to avoid
- Putting a reusable first-party secret in a URL or container command line (cron and callback secrets). `AGENTS.md:1293`
- Trusting claims in the JWT/cookie for authorisation rank instead of re-reading the row. `AGENTS.md:389`
- Marking a COD order's cash collection from a service capability rather than the order's payment method. `AGENTS.md:1027`
- Quoting shipping from weight alone while booking with dimensions. `AGENTS.md:662`
- Using a stored/derived label ("suspended") to decide what the operator's button should do. `AGENTS.md:608`
- Joining `orders` in anything that sums the balance. `AGENTS.md:1055`
- Reporting a credential that was never written (the revealed password verified false against the stored hash). `AGENTS.md:546`
- Writing the audit line with what was requested rather than what the statement returned (`.returning()`). `AGENTS.md:1088`
- Guards that match source text, so a comment or string satisfies them. `AGENTS.md:201`
- Documentation that contradicts the code and stays unfixed. `CUSTOM_DOMAIN.md:18`, `AGENTS.md:345-346`
- A fixed demo/dev password or a prefilled login email on a public login page. `AGENTS.md:~520-530`
- "Defence" list entries that look protective but are no-ops (the TRUNCATE keep-list). `AGENTS.md:~65-72`

## Not applicable to Bukalaris
- KiriminAja and Vultr specifics: Bukalaris uses Mengantar and Coolify, so vendor fields, the sandbox allow-list, and the `KIRIMINAJA_ENV` defaults need re-verification, not copying.
- The Astro storefront performance items: Bukalaris is Next.js. The principles (deferred pixels, real `srcset` widths) apply, but the file names do not.
- Store Builder / Puck page-template and exhaustive-renderer rules: they apply only if Bukalaris adds a similar builder (see ADR-0003).
- Prod-copy local DB (`tokophi-sync-prod`) and the owner-workstation procedures: Bukalaris has its own DEMO and dev data policy.
- PostgREST/VPS production target and Cloudflare Origin CA wildcard details: Bukalaris already decided its routing and hosting (ADR-0008, `docs/08`).
- Landing HTML (`set:html`) owner-only markup: Bukalaris's `docs/12` and `docs/17` already cover sanitising, so only re-check.
- Sandbox CSS, Base UI component quirks and shadcn conventions: tied to TokoΦ's admin stack.

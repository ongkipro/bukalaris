# TokoΦ (tokophi-tasks) — findings for Bukalaris

## Source summary
- TokoΦ is a Shopify-style commerce SaaS for Indonesia: an Astro and Next monorepo, Postgres with Drizzle and RLS, KiriminAja and AutoLaris. KiriminAja here is equivalent to Mengantar, so the shipping findings apply as patterns.
- Sources scanned: `specs/decisions/*` (17 ADRs), `specs/*.md`, `specs/docs/tasks/*` (~95 files, 957 KB), and `apps/docs`. `apps/landing/src` has no `.md` files.
- Date range: Jul–Oct 2026. Some of it is already live on `tokophi.com`, some of it is proposals.
- Scanned by three agents. I only spot-checked some of the "not yet in Bukalaris" claims with a quick grep, so treat **not found** as "needs checking".
- ADR 0016 (buyer account) and 0018 (affiliate commission from seller balance) are not accepted in the source. Do not import them as final decisions.

## Anti-patterns to avoid
- Seeding `current_period_end` with a fixed date: past that date `computeBilling()` returns `readOnly` and every admin save fails, with no clear message (CLAUDE.md "The same rot hits WRITES").
- Do not anchor a *write* to a fixed date: every merchant-created voucher is born already expired, and re-saving shifts the expiry backwards (CLAUDE.md "Never anchor a WRITE to a fixed date").
- Computing `pulih / (pulih + ditinggal)` as the cart rescue rate (CLAUDE.md "The metric trap").
- Falling back all unknown hosts to a single store (T/2026-08-06-open-work.md:981).
- Sending a reusable secret in the query string (`?secret=`, `?token=`): it shows up in `docker inspect`, process lists, and access logs (CLAUDE.md "A REUSABLE FIRST-PARTY SECRET NEVER GOES IN A URL"). Note: `?token=` on the AutoLaris callback is deliberately left open, because the vendor does not send headers.
- Client-side computed fees without a single source shared with billing (T/2026-08-01-audit-wave-money-auth-storefront.md:44-46).
- `selesai`/order status writable by anyone without a recorded source (D/0018:26-42).
- Shipping a feature without a consumer: the `discounts` table and CRUD exist but checkout applies nothing. Rule: every column added must be consumed in the same phase (PROMO_SPEC.md:13-18).
- Moving "done" in only some places: a closed task still written as open in 3 documents makes the next agent redo the fix (CLAUDE.md "A closed task must be closed everywhere").
- `FORCE RLS` on a superuser owner (T/2026-08-22-force-rls-measured-and-refuted.md:44-64) and extending the truncate keep-list for `store_id` tables (a no-op because of cascade) (CLAUDE.md "SEED_FORCE").
